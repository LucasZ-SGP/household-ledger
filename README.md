# 家账 · 家庭收支台账

多币种家庭收支与净资产记账应用。纯前端，无后端服务器 —— 数据以一个 JSON 文件的形式存在你自己的 GitHub 私有仓库里。

- **托管**：GitHub Pages（免费）
- **数据**：你的私有仓库里的 `ledger.json`，每次保存 = 一次 commit，自带版本历史
- **同步**：手机和电脑打开同一个网址，都从同一个仓库读写
- **成本**：0

---

## 一、准备两个仓库

### 1. 代码仓库（公开）

放这份代码，用来跑 GitHub Pages。里面没有任何密钥，公开没问题。

假设叫 `household-ledger`。

### 2. 数据仓库（**必须私有**）

只放你的账本 JSON。**建仓库时一定要选 Private。**

假设叫 `ledger-data`。建好后不用往里放任何东西，应用第一次保存时会自动创建 `ledger.json`。

## 二、部署代码仓库

```bash
# 在这个项目目录里
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<你的用户名>/household-ledger.git
git push -u origin main
```

然后在这个仓库的网页上：

**Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。

选完之后，回到 **Actions** 标签页，会看到 workflow 正在跑（第一次可能需要手动点一下 "Run workflow"）。跑完之后网址是：

```
https://<你的用户名>.github.io/household-ledger/
```

之后你每次 `git push`，Actions 会自动跑测试 + 构建 + 部署。测试不过就不会部署。

## 三、创建 Token

打开 https://github.com/settings/personal-access-tokens/new （Fine-grained tokens）

按这个填：

| 项目 | 填什么 |
|---|---|
| Token name | 随便，例如 `ledger-app` |
| Expiration | 建议 1 年，到期后重新生成再填一次 |
| Repository access | **Only select repositories** → 只勾 `ledger-data` |
| Permissions → Repository permissions → **Contents** | **Read and write** |

其他权限一个都不要给。生成后复制那串 `github_pat_...`，**只显示这一次**。

> 为什么这样配：这个 Token 存在你浏览器的 localStorage 里，只在你自己的设备上。即使某天泄露了，它能碰的也只有 `ledger-data` 这一个仓库的文件内容 —— 碰不到你其他仓库，也改不了任何设置。

## 四、连接

打开部署好的网址 → **设置** → GitHub 同步：

- GitHub 用户名：`<你的用户名>`
- 仓库名：`ledger-data`
- 文件路径：`ledger.json`

## 五、日常使用

1. 银行账单出来 → **导入账单** → 上传 PDF（OCBC）或 CSV/Excel
2. PDF 会自动识别版式并做对账校验；CSV/Excel 需要选一下哪列是日期、哪列是金额
3. 预览确认无误 → 导入。已存在的交易会自动跳过，同一份账单重复导入不会产生重复记录
4. 认不出来的交易进 **待确认**，按描述自动分组，一次确认整组
5. 确认时可以直接 **+ 新建分类**，不用局限于预设的类别
6. 勾选「记住规则」，下次同样的商户自动归类 —— 用得越久，需要手动确认的越少
7. 到 **月度结算** 看这个月挣了多少、花了多少，把结余分配到定期存款或提前还贷，直到「待分配」归零
8. 资产、负债在 **资产负债** 页登记一次，之后利息、市值、欠款自己往前走
9. **点右上角「保存到 GitHub」** ← 这一步不能省，否则换设备看不到

> 保存是手动的，因为每次保存都是一次 git commit。如果自动保存，敲一个字就会产生一次提交，历史记录会没法看。

## 六、月度结算

资产负债表是**存量** —— 某一天你有多少。这一页管的是**流量**：这个月挣的钱最后去了哪。

一个月的账是这样结的：

```
本月收入        工资性收入 + 资本利得 + 其他
− 本月支出      来自交易记录
─────────────
= 本月结余
− 已分配        转化为资产（定期/股票/CPF…）+ 消除负债（提前还贷）
─────────────
= 待分配        目标是 0
```

**待分配归零，这个月就结清了。** 这个数字不是用来欣赏的，是用来清掉的 —— 钱要么花掉了（已经在支出里），要么变成了某项资产，要么用来还了债。剩下一个说不清去向的数，本身就是有用的信息。

**收入不用重复录入。** 账单导入之后，分类为「工资/奖金」的自动进「工资性收入」，「资本利得」和「利息」进「资本利得」。手动补录只用于不走银行账单的钱：CPF 缴纳、留在券商账户里的股息、现金收入。手动补的那几笔会单独标出来，跟账单来的分开显示。

**分配到哪里。** 下拉框里是你在资产负债页建的账户，分成「转化为资产」和「消除负债」两组。房产和汽车不在列表里 —— 它们本来就不记金额，承接不了钱。

**和贷款台账对照。** 分配到贷款的那一笔，旁边会显示这个贷款账户本月实际记到的还款额。两个数字对不上不一定是错（比如月供是 CPF 扣的，没占用你的现金结余），但对得上的时候会明确告诉你「与台账一致」。

分配记录**不会**自动去改账户余额 —— 你的房贷记录是从银行对账单导入的，如果这里再写一遍就重复了。这一页记的是「钱的去向」，资产负债页记的是「实际发生了什么」，两边独立、互相印证。

## 七、资产负债

收支记的是流水，这一页记的是**存量** —— 你有多少、欠多少，以及它们会自己怎么变。

登记一次之后，下面这些不用再手动更新：

| 类型 | 你填什么 | 应用自动算什么 |
|---|---|---|
| **银行定期** | 本金、年利率、起息日、存期（或到期日）、单利还是按月复利 | 到今天为止的应计利息、当前价值、到期本息、还剩几天；到期后利息停止增长并提醒你去转存 |
| **股票账户** | 代码、股数，以及各币种的闲散资金（SGD 5,000 和 USD 1,000 各记各的） | 打开页面就自动取当天价格并算市值（50 股 QQQ 就是 50 × 现价），按币种分开小计 |
| **CPF** | OA / SA / MA / RA 四个户头的余额、出生年份 | 基础利息 + 额外利息（55 岁以下首 6 万 +1%；55 岁及以上首 3 万 +2%、次 3 万 +1%，其中 OA 只算前 2 万），给出预计年利息 |
| **房贷 / 其他贷款** | 放款金额、年利率（默认 2.6%）、放款日、每月计息日（默认 1 号）、月供 | **每月计息日自动加一个月利息**（余额 × 年利率 ÷ 12，四舍五入到分），加上你记的每笔还款，算出当前欠款、累计利息、还清还需多少个月。支持粘贴导入银行对账单，见下 |
| **房产 / 汽车** | 只填名字和一句说明 | 不记金额、不计入合计，在总览里以名字列出（见下） |
| **现金 / 其他资产** | 余额或估值 | 按年利率估算一年利息 |

几个设计上的选择，用之前值得知道：

**贷款余额是算出来的，不是存下来的。** 每次打开都从放款日重新按月推一遍：利息 → 还款 → 利息 → 还款。所以三个月没打开应用，回来看到的数字和天天打开是一样的；哪个月漏记了也不会被悄悄跳过。利率中途调过就记一笔「利率变更」，跟银行对不上就记一笔「余额校准」—— 都在时间线里看得见。

**不做汇率换算。** 和总览页一样，每个币种各算各的：USD 的股票就报 USD，SGD 的房贷就报 SGD。省得凭空造一个汇率，把两个月后回头看的人绕晕。

**没有价格的持仓不算 0，而是明确告诉你缺价。** 合计里少一个数，总比一个看起来完整、实际漏了一半的数字要好。

**房子和车只记名字，不记金额。** 它们会以名字的形式列在总览里，但不进资产合计 —— 任何写在房子或车上的「现值」本来就只是个估计，一旦进了净资产总额，过几个月就会变成一个没人记得更新、却看起来很确定的数字。真想给某样东西估个价，用「其他资产」记一笔，那里的数字是你主动填的，你知道它是什么。

页面上的「生成净资产快照」会把当天的资产负债合计写进净资产页，历史曲线就自然接上了。

### 贷款：完整台账与对账单导入

展开贷款账户能看到一份和银行对账单一样的完整流水：每一行都带原始代码（`IP-2.60`、`AXS-L`、`INT-R`…）、金额和之后的余额，可以按年筛选，也能看每年的利息/月供/提前还款小计。每条记录都能改、能删，改完余额会从头重算一遍。

**不用一条条敲。** 点「导入对账单」，把银行 Statement of Account 里的表格整段粘贴进去就行。认识这些代码：

| 代码 | 含义 | 对余额 |
|---|---|---|
| `BAL-BF` / `BAL-CF` | 期初 / 期末余额 | 校验点 |
| `RES` / `RES-I` | 放款 / 放款利息 | + |
| `IP-2.60` | 每月按 2.60% 计的利息 | + |
| `CPF` | 每月 CPF 扣款 | − |
| `AXS-L` / `CPF-A` / `CPF-L` | 提前还款 | − |
| `AXS-I` | 还利息 | − |
| `INT-R` | 提前还款的利息回扣 | − |

导入前会做两道校验，跟账单导入是一个思路：

1. **对账**：把所有记录 replay 一遍，看期末余额是否等于对账单自己打印的 `BAL-CF`。对不上会明确告诉你差多少，并且挡住导入（除非你勾选「我知道对不上，仍要导入」）。
2. **利息复算**：每一笔 `IP` 是否等于「上月余额 × 利率 ÷ 12」。这一步是用来抓看错数字的 —— 少读一位，这里立刻就炸了。

重复导入是安全的：按「日期＋类型＋金额」计数去重，所以同一天两笔一模一样的 CPF 扣款都会保留，而重叠的年份只会补上缺的那部分。

导入之后，**最后一期对账单之后的月份由应用自己往下算** —— 对账单里已经写明的月份用对账单的数字，没写的月份按余额 × 利率 ÷ 12 生成，两者不会重复。

### 提前还款的利息回扣

这一条值得单独说，因为它容易算错：**每月 1 号的利息是按月初余额一次性收整月的**，所以你月中提前还一笔，银行会把「这笔钱本月剩余天数对应的那部分利息」退回来。

```
回扣 = 还款额 × 年利率 ÷ 12 × 当月剩余天数 ÷ 当月天数
```

记一笔提前还款时，应用会自动按这个公式算好回扣一起记上（金额可以改）。这个公式是拿真实对账单反推出来的，25 笔 `INT-R` 全部对上，一分不差。

### 关于股票价格

配好行情源之后，**打开「资产负债」页就会自动取当天的价格**，不用点任何按钮。已经是当天价的不会重复取（免费额度有限），所以一天只会取一次；想手动刷新随时可以点「刷新行情」。

应用没有后端，取价是**从你的浏览器直接发请求**，所以行情源必须允许跨域（CORS）。这一点各家差别很大，所以设置里可以选：

| 行情源 | 要 Key 吗 | 免费额度 | 备注 |
|---|---|---|---|
| Finnhub | 要（免费注册） | 60 次/分钟 | 一般能直接在浏览器里调，推荐先试这个 |
| Twelve Data | 要（免费注册） | 800 次/天 | 会返回报价币种，非美股（如 `D05.SI`）比较合适 |
| Alpha Vantage | 要（免费注册） | 约 25 次/天 | 额度小，持仓少的话够用 |
| Stooq | 不要 | — | 免注册，但通常要配代理；美股代码写成 `qqq.us` |
| Yahoo Finance | 不要 | — | 覆盖最全，但基本一定要配代理 |
| 手动输入 | — | — | 不联网，在持仓行点铅笔图标自己填价 |

设置页有个「用 QQQ 测一下」按钮，直接打一次真实请求，能不能用一试便知 —— 不用猜。

被浏览器以跨域为由拦下时有三条路：换一个行情源、填一个代理地址（支持 `https://…/?url={url}` 模板，建议用自己部署的 Cloudflare Worker，因为代理方能看到你查了哪些代码）、或者干脆手填价格。

取到的价格会连同账本一起存进仓库，所以离线打开、或者哪天额度用完了，数字依然是齐的 —— 只是会标出「偏旧」。手填的价格也一样：当天有效，第二天自动取价会把它换掉（除非行情源选的就是「手动输入」）。

**API Key 存在浏览器 localStorage 里，和 GitHub Token 一样不写进账本文件、不进仓库。**

### 关于 CPF

**CPF 没有面向个人的公开 API。** 余额只在 Singpass Myinfo 里拿得到，而 Myinfo 是需要企业签约、按次收费的服务器端接口（server-to-server，要客户端密钥 + 白名单回调），纯前端的静态页面既拿不到资质也存不住那种凭证。CPF 官方 App 也没有导出接口。

所以这里的做法是：余额你从 CPF App 抄进来（一年动一两次的东西，不算负担），能自动算的利息部分由应用来算。利率默认按官方的 OA 2.5% / SA、MA、RA 4%，可以自己改。

需要注意这是**估算**：CPF 实际按每月最低余额计息、每年 1 月 1 日入账，而这里是按当前余额推一年的利息，真实数字会有出入。

## 八、几个要知道的点

**关于冲突**：如果手机和电脑都改了同一份账本，后保存的一方会被拒绝，应用会弹出选择：用本地覆盖远端，还是丢弃本地重新拉取。两份内容都在 GitHub 的提交历史里，事后能找回。

**关于版本历史**：设置页有「查看历史版本」链接，能看到每次保存的 diff —— 哪天改了什么一目了然。误操作了可以在 GitHub 上回滚。

**关于 CSV 格式**：如果金额里的千分位逗号没有加引号（`-2,500.00` 而不是 `"-2,500.00"`），列会错位，金额会变成 `-2`。应用会检测到并挡下来要求你确认。碰到这种情况，最简单是用 Excel 打开另存一次，或者直接上传 .xlsx。

**关于 PDF**：支持 OCBC 的 Statement of Account，纯本地解析（pdf.js），不需要 API key、不联网、文件不上传。

解析后会用账单自身的数据做三重校验：逐笔 running balance 必须连续、期初±收支必须等于期末、汇总必须等于账单打印的 Total。三项全过才允许一键导入；任何一项不过会明确告诉你哪几行对不上，并要求你逐笔核对后才能继续。

其他银行需要先看样本再写适配（`src/lib/statements/` 下加一个模块即可）。想验证自己的账单，可以本地跑：

```bash
node tests/realpdf.mjs ~/Downloads/statement.pdf
```

会打印交易笔数和对账结果，不写入任何数据。

## 九、本地开发

```bash
npm install
npm run dev     # 本地预览
npm test        # 跑测试（291 个）
npm run build   # 构建
```

测试分三层，共 291 个：
- `tests/run.mjs` —— 246 个单元测试：日期/金额解析、分类规则、去重签名、UTF-8 base64 往返、GitHub API 错误码映射；OCBC PDF 解析（列定位、跨行描述拼接、流水号剥离、跨年推断、跨页交易、对账校验能否抓出金额读错/方向反了/漏读/重复）；以及资产负债那套算术 —— 月末进位的日期推算、定期到期后停止计息、贷款按月计息与还款的先后顺序、漏了几个月照样补齐、还款超过余额不会变成负数、CPF 额外利息分档、缺价持仓不计入合计、行情源的返回格式与错误码；以及一整套以 HDB 对账单为基准的贷款测试 —— 拿一份 26 个月、135 条记录的对账单（结构照搬真实账单，金额是重算过的虚构数据，仓库里不放任何人的真实房贷），三份对账单各自 replay 出来的期末余额必须与打印值一分不差，25 笔月度利息必须等于「余额 × 利率 ÷ 12」，25 笔利息回扣必须等于剩余天数公式，改错一个数字或漏掉一行都必须被抓出来；另外单独钉了几个来自真实账单的数字，用来证明公式对得上银行、而不只是自洽；以及月度结算那套恒等式 —— 收入只从交易记录读一次不重复计、手动补录只补账单没有的、结余分配到资产与负债的归类、分配超出结余会被标出、分几分钱也不会让「待分配」偏离零
- `tests/integration.mjs` —— 45 个集成测试：jsdom 里挂载真实应用配一个假 GitHub 仓库，走完整流程（导入 → 确认分类 → 新建分类 → 登记定期/房贷/股票 → 记提前还款并自动带出回扣 → 改记录 → 删记录 → 粘贴导入三年对账单并对账 → 重复导入去重 → 手填价格 → 分币种记闲散资金 → 登记房产/汽车并确认它们不动合计 → 生成快照 → 保存 → 冲突 → 换设备重新加载 → 配好行情源后重开页面，确认价格自动取到、当天不重复取）
- `tests/realpdf.mjs` —— 本地手动跑，拿真实 PDF 验证解析与对账（不进 CI，仓库里不放任何真实账单）
